🚦

先告诉你什么时候「不用组队」

多数多 Agent 翻车，都从「Agent 越多越好」这个念头开始。任务进来先过一张前置判断清单：真的能拆成互相独立的子任务吗？还是一个 Agent 干得更利索？简单顺序任务会被礼貌劝退。

省下的是 token、等待时间，以及几个 Agent 互相转述打圈圈的那种特殊混乱。
前置判断清单
🧭

你只说任务，队形它来定

没有模式菜单，也没有连线图。带调研味的活自动走指挥官队形（真正并行、带工具）；多角度分析、批量翻译这类纯文本任务走快速流水线；「先调研，再给我三个版本」自动变成两阶段的混合模式。

你继续谈结果，排兵布阵交给它。

📜

三条铁律，守着队伍最容易散的地方

可拆分性必须先判断，单一顺序任务绝不强行并行；派活保持极简——「谁 + 做什么」，一个字不多附；主 Agent 亲自汇总验证结果，子 Agent 的原始输出不会被直接粘贴给你。

还有一张 9 条常见坑的对照表：沉默开局、token 爆炸、假忙转述、意大利面连线……每条都写明错的做法和对的改法。
3 条铁律 · 9 坑对照
🔎

写的人，永远不给自己打分

刚写完报告的 Agent，往往会相当喜欢自己的报告。这个 Skill 把执行和评审切开：一个全新上下文的评审 Agent，按五维评分表——事实、结构、逻辑、证据、格式——逐项打分。

结果只有两种：通过，或一份具体的修改清单。同一个模型，判断明显更靠谱——因为打分的人不在写作现场。
评审分离 · 5 维评分表
📊

每次跑完，交一张「战报」

每一轮结束都有标准统计卡：哪些 Agent 上场了、什么角色、耗时多少、状态如何、并行比串行省了多少时间、主对话的上下文被隔离掉多少。

统计卡没输出、结果没合流、评审没通过之前，任务不算完成。
执行统计卡
🪂

环境不支持子 Agent？也能稳稳落地

如果你的 Agent 运行时压根派不出子 Agent，主 Agent 会依次扮演每个角色：流水线模式完整可用，评审分离改用「隔一段上下文再审」来保住独立性。说实话，比真并行慢——但不装快。

4 个抽象契约（spawn · monitor · history · notify）按能力签名对号入座。不用装框架、不用 Python、零依赖。

🚀 核心工作流

三种模式，自动路由

你不必特意说「组队」。任务自然拆成两个以上独立子任务、需要同时查多个信息源、同类任务成批出现、或产出高风险内容时，它会自己醒来；专项 Skill 或简单顺序就能搞定的任务，它保持安静——这是设计如此。

🎯 指挥官模式

多方向/多信息源调研，需要联网和工具，真并行。

触发：「同时调研 A、B、C 三个方向」

🔄 流水线模式

纯文本任务：多角度分析、多风格写作、批量翻译。

触发：「用三个角度分析这个问题」

🔀 混合模式

先调研，再多版本输出。

触发：「调研完给我三版不同风格的文案」

📦 背景怎么传给子 Agent

  • 背景注入（默认）：任务前附一行「[背景] 谁在做什么、给谁看」。
  • 前序结果传递：串行环节中，上一个 Agent 的发现以结构化要点传给下一个。
  • 读文件：背景较重时，让子 Agent 读一个背景文件，而不是贴一屏文字。

🧵 拓扑原则——拒绝意大利面

只允许：线性（A → B → C）· 扇出（A → [B, C, D] → E）

加任何连接前先问三句：B 真的需要 A 的产出吗？没有它 B 能独立干活吗？这条连接是不是「以防万一」加的？是，就删。
